# Developer notes

## Architecture
- **Boot**: `GameManager.Boot()` runs via `[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]` in any scene. It disables
  scene cameras/lights and builds everything (UI canvas, audio, menu showroom). No prefabs or scene content needed.
- **Screens**: Main menu → Character select → Track select → `LoadRace()` coroutine → `RaceManager` → results overlay.
- **Rendering**: Built-in RP, one vertex-colour toon shader (`ToonVC`) with wrap lighting, soft band, rim, and *custom*
  distance fog driven by globals (`_TT_FogColor/_TT_FogParams`) so fog survives shader-variant stripping on Android.
  Shaders live in `Resources` so they are always included in builds.
- **Physics layers** (by index, no TagManager edits): 8 = Ground (road/terrain/kickers/ice MeshColliders). Walls are
  analytic (spline lateral clamp), which is tunnelling-proof at turbo speeds and cheap on phones.

## AI (AIDriver.cs)
Yaw-rate controller: desired yaw = path curvature × speed + 2.6 × heading error to a curvature-biased racing line.
Slides when the peak turn rate ahead exceeds normal steering (or is worth farming turbos); maps desired yaw onto the
slide's tight..wide range; releases when the bend ends. Turbo timing window depends on `Skill`. Lines up pads/ramps
via `TrackInstance.AiLane`. Rubber-banding in `RaceManager.UpdateRace`.

## Track format v2 (`Assets/Resources/TurboTribe/Tracks/*.json`) — generated by `Tools/trackgen`
- `roads[0]` = closed main loop; `roads[1..]` = open branches `{id, kind: shortcut|route, from{t}, to{t}, points}` that
  leave/rejoin the main road (anchored on main samples; surfaces stay level where they overlap, the gore keeps walls).
- `zones[{a,b,style}]` – environment per main-road span (beach, jungle, temple, volcano, desert, mine, mesa, river,
  village, icecave, lake, alpine). Branches inherit through their main-index mapping.
- `ranges[{road,type,a,b}]` – gap, tunnel, ice, open/openL/openR (shoulders), cliff/cliffL/cliffR (drop → respawn),
  low/lowL/lowR (low jumpable walls), bareL/bareR (no wall, no shoulder), trail (secret path look).
- `events[{road,type,t,...}]` – ramp, pad, crates, mud, bump/dip/rumble (vertical profile features),
  hump (half-road mound: lane ±1 = left/right half, or a lateral fraction + width), curtain (hanging strands over a branch).
- branch flags: `hidden` (secret: no minimap/signs, CPUs need skill ≥ 0.6), `detachStart/detachEnd` (end beside the road,
  reached over a low wall / off a ledge - no main anchors, no wall opening).
- `obstacles[{road,type,t,lane,size,period,phase,count,spread}]` – pillar, crab, boulder, pendulum, geyser, penguin, pusher.
- `landmarks[{type,x,z,r,y}]` – lagoon (water basin), lava (glowing pool), ice (frozen lake), volcano, pyramid, stonehead, mesa, crystal, rock.
- Parameters `t/a/b` are control-point units of that road's spline.

### Authoring (`Tools/trackgen/*.py`)
Turtle DSL: `S(len, y, prof, w)`, `T(angle, radius, y, ...)` (+ = right), elevation profiles smooth/steep/early/late/crest,
`M(mark)`, two `FREE()` straights solved for exact loop closure (total turning ±360, 0 for a figure-8, 720 with a loop),
`V()` straights solved by `constrain(markA, markB, dx, dz)` (used to line up the bridge crossing), branches via Hermite
waypoints relative to marks, content placed in metres from marks. `python3 tiki_island.py` writes the JSON;
`python3 preview.py track.json out.png` draws layout/elevation and prints radii, slopes and overlap warnings.

## Verification tools (no Unity needed)
- `python3 Tools/trackgen/jumpsim.py` – 2-D model of the kart's vertical physics (snap, predictor, natural launch, lip
  jump, air time) with the C# constants; prints air time / height / distance per profile and press timing.
- `python3 Tools/trackgen/validate_secrets.py track.json` – for each hidden shortcut: real road profile (incl. the main
  surface under an overlapping branch, kickers, humps, gaps), simulated at 27/30/34 m/s with no input and with lip jumps
  pressed 0.30/0.15/0.06 s early → FALL / main (landed back on the normal road) / ok. Low-wall hops are checked with
  `check_hops` (where the launch line crosses the wall, height there, where the branch surface starts).
- `pwsh Tools/HeadlessShim/run_sim.ps1 -Proj . -Track tiki_island -Laps 3 -Skills "0.3,0.6,0.9,1.0"` – compiles the
  *real* TrackBuilder, KartController, AIDriver and ObstacleManager against a small UnityEngine shim (with a
  ray/triangle Physics.Raycast) and races AI karts: lap times, wall bonks, falls, hazard hits, turbos, branch usage.
- `pwsh Tools/HeadlessShim/run_sim.ps1 -Proj . -Mode export -OutDir /tmp/exp` – OBJ export of every track + karts;
  `python3 Tools/webgl_render.py` / `Tools/render_karts.py` render them (WebGL toon imitation, alpha-tested foliage).
- Roslyn compile check against the Unity 6 reference assemblies.

Latest headless race (8 AI, skills 0.2–1.0, 3 laps): Tiki Island 62–73 s/lap, Dustbowl Canyon 62–72 s, Glacier Peak
56–72 s; 0–1 falls per race (only off cliff/lava edges), every branch used by the AI.
