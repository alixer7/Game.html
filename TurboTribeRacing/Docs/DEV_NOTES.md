# Developer notes

## Architecture
- **Boot**: `GameManager.Boot()` runs via `[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]` in any scene. It disables
  scene cameras/lights and builds everything (UI canvas, audio, menu showroom). No prefabs or scene content needed.
- **Screens**: Main menu → Character select → Track select → `LoadRace()` coroutine → `RaceManager` → results overlay.
- **Rendering**: Built-in RP, one vertex-colour toon shader (`ToonVC`) with wrap lighting, soft band, rim, and *custom*
  distance fog driven by globals (`_TT_FogColor/_TT_FogParams`) so fog survives shader-variant stripping on Android.
  Shaders live in `Resources` so they are always included in builds.
- **Physics layers** (by index, no TagManager edits): 8 = Ground (road/terrain/kickers/ice MeshColliders). Walls are
  analytic (spline lateral clamp), which is tunnelling-proof at turbo speeds and cheap on phones.

## AI (AIDriver.cs)
Yaw-rate controller: desired yaw = path curvature × speed + 2.6 × heading error to a curvature-biased racing line.
Slides when the peak turn rate ahead exceeds normal steering (or is worth farming turbos); maps desired yaw onto the
slide's tight..wide range; releases when the bend ends. Turbo timing window depends on `Skill`. Lines up pads/ramps
via `TrackInstance.AiLane`. Rubber-banding in `RaceManager.UpdateRace`.
v0.4: **corner-speed planner** (looks ~8 + 1.25·v m ahead; the kart's best yaw rate × 0.82–0.95 by skill; flicks cost
12 %); **lip jumps** use an own countdown to the predicted takeoff (the predictor steps in 45 ms nodes) with a
skill-based lead ≥ 0.045 s; jump shortcuts: no slide-hops on the run-up, line-up ~45 samples early, aim at the
branch launcher's centre; secret launchers on the main road (`Road.SecretLane`) are avoided when not going for them;
a branch the CPU fell off is not retried that lap; drops on the inside of tight bends clamp the line; hazard dodging
never pushes towards a cliff. Hidden shortcuts: skill ≥ 0.75 only. Tool hooks: `ForceBranch`, `NeverBranch`,
`LipLeadOverride`.

## Track format v2 (`Assets/Resources/TurboTribe/Tracks/*.json`) — generated by `Tools/trackgen`
- `roads[0]` = closed main loop; `roads[1..]` = open branches `{id, kind: shortcut|route, from{t}, to{t}, points}` that
  leave/rejoin the main road (anchored on main samples; surfaces stay level where they overlap, the gore keeps walls).
- `zones[{a,b,style}]` – environment per main-road span (beach, jungle, temple, volcano, desert, mine, mesa, river,
  village, icecave, lake, alpine). Branches inherit through their main-index mapping.
- `ranges[{road,type,a,b}]` – gap, tunnel, ice, open/openL/openR (shoulders), cliff/cliffL/cliffR (drop → respawn),
  low/lowL/lowR (low jumpable walls), bareL/bareR (no wall, no shoulder), trail (secret path look).
- `events[{road,type,t,...}]` – ramp, pad, crates, mud, bump/dip/rumble (vertical profile features),
  hump (half-road mound: lane ±1 = left/right half, or a lateral fraction + width), curtain (hanging strands over a branch).
- branch flags: `hidden` (secret: no minimap/signs, CPUs need skill ≥ 0.6), `detachStart/detachEnd` (end beside the road,
  reached over a low wall / off a ledge - no main anchors, no wall opening).
- `obstacles[{road,type,t,lane,size,period,phase,count,spread}]` – pillar, crab, boulder, pendulum, geyser, penguin, pusher.
- `landmarks[{type,x,z,r,y}]` – lagoon (water basin), lava (glowing pool), ice (frozen lake), volcano, pyramid, stonehead, mesa, crystal, rock.
- Parameters `t/a/b` are control-point units of that road's spline.

### Authoring (`Tools/trackgen/*.py`)
Turtle DSL: `S(len, y, prof, w)`, `T(angle, radius, y, ...)` (+ = right), elevation profiles smooth/steep/early/late/crest,
`M(mark)`, two `FREE()` straights solved for exact loop closure (total turning ±360, 0 for a figure-8, 720 with a loop),
`V()` straights solved by `constrain(markA, markB, dx, dz)` (used to line up the bridge crossing), branches via Hermite
waypoints relative to marks, content placed in metres from marks. `python3 tiki_island.py` writes the JSON;
`python3 preview.py track.json out.png` draws layout/elevation and prints radii, slopes and overlap warnings.

## Verification tools (no Unity needed)
All of them run the REAL game code through `Tools/HeadlessShim` (UnityShim + ray/triangle Physics) with the .NET 8 SDK:
- `Tools/HeadlessShim/run_sim.sh sim <track> [laps] [skills] [seed] [trace.csv]` – races CPU karts (KartController + AIDriver +
  ObstacleManager on the real geometry): lap times, wall bonks (impact), falls, hits, turbos, air time, branch usage.
- `run_sim.sh shortcuts <track>` – **the authoritative shortcut test**: for every branch a skill-1 CPU is forced onto it
  starting 140 m before the junction, with lip-jump lead times none / 0.28 / 0.20 / 0.14 / 0.09 / 0.05 / 0.02 s, Balanced
  and Speed class, plain and with a turbo picked up ~60 m before the junction, 3 seeds each → success ratio + time to a
  point 60 m past the rejoin vs the main road. `TT_TRACE=branch:class:turbo:lead:seed` prints a per-frame trace.
  (`Tools/trackgen/jumpsim.py` / `validate_secrets.py` are the old 2-D approximations; they disagreed with the real
  code - trust the shortcut test.)
- `run_sim.sh export <dir>` – OBJ (with vertex normals) of every track + all karts; `Tools/webgl_render.py` /
  `Tools/render_karts.py` render them (smooth-shaded WebGL toon imitation, alpha-tested foliage; set `PW_CHROMIUM` to a
  Chromium binary if Playwright's own is not installed).
- `python3 Tools/check_scene.py <dir>/<track>.obj <track>.json` – splits every prop/landmark mesh into assemblies and
  reports any that **float** (> 0.6 m above the terrain, not on a deck) or **intrude** into a road corridor. v0.4: 0/0 on
  all tracks.
- `run_sim.sh ray <track> x z ...` – lists the surfaces under a point (debugging).
- `python3 Tools/trackgen/preview.py track.json out.png` – layout / elevation / overlap warnings.
- Compile check: build all of `Assets/**/*.cs` against Unity reference assemblies (e.g. the NuGet packages
  `UnityEngine.Modules`, `Unity3D.UnityEngine.UI`, `Unity3D.SDK`).

v0.4 headless race (8 CPUs, skills 0.2–1.0, 3 laps): Tiki Island 55–70 s/lap (2 falls), Dustbowl Canyon 68–81 s (9),
Glacier Peak 60–80 s (4) – the falls are failed shortcut attempts by the top CPUs.

## Sculpted graphics (v0.4)
- `Core/Sculpt.cs`: SDF primitives (ellipsoid, tapered capsule), smooth union/subtraction, 3D value noise / fbm, and
  `Radial()` – meshes a star-shaped SDF as one lat/long surface (rays from a centre, march + bisection), normals from
  the SDF gradient, colour from a callback. `Hit()` finds surface points (to seat eyes, noses, lava streams...).
- Heads (`KartMeshes.BuildHead`): cranium + jaw + cheeks + brow ridge + species muzzle blended; eye sockets and smile
  crease carved; markings painted from SDF masks; 44×72 rays (22×36 for the LOD). Kart meshes are cached per
  character (`KartModel.BodyMesh`).
- `Track/OrganicProps.cs`: Canopy, Rock, PineTier, RibbedTube (cactus), Butte, Volcano. LOW quality meshes them at 2/3
  resolution.
- Placement rules: props seat on the lowest ground of their footprint (`TrackTerrain.SeatHeight`), tunnels get terrain
  ridges up to their crown, lava basins fill pits up to their bed, trackgen slides landmarks clear of all roads.

## Authoring additions (v0.4)
`t.clear_from(branch)` – where a branch fully clears the main road (height-aware); launchers and gaps are placed from
it. `t.curtain_spot(branch, width)` – where a curtain's posts stand clear of every road. `edge_clearance(..., y=)` ignores
roads on another level. Landmarks are pushed outwards until 2 m clear of every road (printed when moved).
